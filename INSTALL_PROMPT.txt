# CachyOS Dotfiles — инструкция для GPT

Ты помогаешь восстановить конфигурацию CachyOS + Hyprland из этого репозитория.

Цель:
восстановить пользовательскую графическую среду после переустановки CachyOS максимально близко к исходному состоянию, не затрагивая приватные и несвязанные данные пользователя.

============================================================
ОСНОВНОЙ INSTALLER
==================

В корне репозитория находится:

```
install.sh
```

Это основной и предпочтительный способ восстановления конфигурации.

Перед ручным копированием файлов сначала изучи install.sh.

Не создавай альтернативный installer и не переписывай существующий install.sh
без явной необходимости и отдельного запроса пользователя.

install.sh намеренно:

* не запускается от root/sudo;
* не устанавливает пакеты автоматически;
* не изменяет /etc;
* не удаляет ~/.config целиком;
* работает только с явно определённым whitelist конфигураций;
* перед удалением существующего managed target создаёт backup;
* не смешивает старую и новую конфигурацию;
* восстанавливает конфигурацию из репозитория как source of truth;
* не перезапускает Hyprland автоматически.

============================================================
СТРУКТУРА РЕПОЗИТОРИЯ
=====================

Основные пользовательские конфигурации:

```
config/hypr/       -> ~/.config/hypr/
config/noctalia/   -> ~/.config/noctalia/
config/kitty/      -> ~/.config/kitty/
config/fish/       -> ~/.config/fish/
config/gtk-3.0/    -> ~/.config/gtk-3.0/
config/gtk-4.0/    -> ~/.config/gtk-4.0/
config/qt5ct/      -> ~/.config/qt5ct/
config/qt6ct/      -> ~/.config/qt6ct/
config/xsettingsd/ -> ~/.config/xsettingsd/
config/kdeglobals  -> ~/.config/kdeglobals
```

Визуальные assets:

```
assets/
└── wallpapers/
    └── lunar-tides-5120x4266-26444.jpg
```

Фактический список managed targets определяется массивом MAPPINGS
в install.sh.

Не придумывай дополнительные managed targets, которых нет в MAPPINGS.

Assets, находящиеся в repository, не обязательно являются managed targets
и не должны автоматически копироваться в ~/.config, если это отдельно
не предусмотрено install.sh или явно не запрошено пользователем.

============================================================
ПОЛИТИКА БЕЗОПАСНОСТИ
=====================

1. Не удаляй существующие пользовательские конфиги без backup.

2. Перед изменением существующего managed target install.sh создаёт
   отдельную backup-копию в:

   ```
   ~/.config-backups/<timestamp>/
   ```

3. Не удаляй ~/.config целиком.

4. Не выполняй rm -rf для произвольных путей.

5. Не изменяй файлы за пределами managed scope без явного запроса
   пользователя.

6. Не трогай:

   * браузеры;
   * VPN;
   * SSH;
   * пароли;
   * credential/session data;
   * dconf;
   * pulse;
   * другие приватные/runtime-конфиги,

   если они явно не добавлены в репозиторий и managed scope.

7. Не копируй .git внутрь пользовательских конфигурационных директорий.

8. Не изменяй /etc без явного указания пользователя.

9. Не используй sudo для копирования пользовательских конфигов
   в ~/.config.

10. Не устанавливай случайные пакеты.

11. Если для работы конфигурации отсутствует приложение или пакет,
    сначала сообщи пользователю, что именно отсутствует и зачем оно нужно.

12. Если команда может удалить или перезаписать данные,
    сначала объясни пользователю последствия.

13. Не изменяй Noctalia, Hyprland или другие конфиги только ради
    автоматического назначения wallpaper, если пользователь явно
    этого не просил.

============================================================
BACKUP И RESTORE
================

Архитектура install.sh для каждого managed target:

```
backup
   ↓
safe_remove
   ↓
mkdir parent
   ↓
cp -a
   ↓
chown
```

Это намеренно НЕ merge-поведение.

Если, например:

```
~/.config/hypr/
```

существует, installer сначала сохраняет старый каталог в backup,
после чего удаляет старый managed target и копирует версию из репозитория.

Это предотвращает накопление устаревших файлов, которых больше нет
в репозитории.

Если исходник в repository отсутствует, install.sh НЕ должен удалять
существующий target пользователя.

Такой target пропускается с warning.

Backup должен быть создан до удаления существующего managed target.

Не восстанавливай конфигурацию поверх существующей директории
простым копированием, если это создаёт merge-поведение и оставляет
старые файлы, которых больше нет в repository.

============================================================
ОКРУЖЕНИЕ
=========

После установки необходимо проверить наличие программ, используемых
конфигурацией.

В частности обратить внимание на:

* Hyprland
* UWSM
* Noctalia
* Kitty
* Fish
* qt5ct
* qt6ct
* xsettingsd
* hyprpicker
* другие программы, реально упомянутые в конфигурациях

Не предполагай наличие программы только потому, что её конфигурация
есть в repository.

Сначала проверь конфиги и PATH.

Если программы нет:

* сообщи её название;
* объясни, какой конфиг или функция от неё зависит;
* предложи подходящий пакет или способ установки;
* не устанавливай его молча.

Не устанавливай пакеты только потому, что их название встречается
в комментарии или неиспользуемом фрагменте конфигурации.

============================================================
HYPRLAND
========

Hyprland использует Lua-конфигурацию.

Обязательно сохраняй структуру:

```
~/.config/hypr/hyprland.lua
~/.config/hypr/config/
```

Не объединяй Lua-файлы в один файл без явной необходимости.

Особенно важны:

```
config/animations.lua
config/autostart.lua
config/binds.lua
config/colors.lua
config/decorations.lua
config/environment.lua
config/inputs.lua
config/misc.lua
config/monitors.lua
config/variables.lua
config/windowrules.lua
config/workspaces.lua
```

При проверке обращай особое внимание на:

* monitor configuration;
* workspace assignment;
* keyboard layouts;
* keybindings;
* window rules;
* decorations;
* opacity;
* blur;
* colors;
* startup applications;
* UWSM integration;
* Noctalia integration.

Если конфигурация использует:

```
uwsm app -- ...
```

или:

```
noctalia msg ...
```

проверь наличие соответствующих программ.

Не меняй структуру Lua-конфигурации только ради упрощения.

============================================================
ОБОИ, ТЕМЫ, ШРИФТЫ И ASSETS
===========================

Конфигурационные файлы сами по себе не гарантируют наличие всех
визуальных ресурсов.

В repository уже добавлен wallpaper:

```
assets/wallpapers/lunar-tides-5120x4266-26444.jpg
```

Это сохранённый визуальный asset/backup.

Wallpaper не является managed ~/.config target.

Не изменяй автоматически настройки Noctalia, Hyprland или других
программ, чтобы назначить этот wallpaper.

Если пользователь хочет использовать wallpaper, сообщи ему путь:

```
assets/wallpapers/lunar-tides-5120x4266-26444.jpg
```

Назначение wallpaper пользователь выполняет самостоятельно.

При анализе конфигурации также проверяй:

* wallpaper paths;
* GTK themes;
* Qt themes;
* icon themes;
* cursor themes;
* fonts;
* Kitty themes;
* Noctalia assets;
* изображения и другие файлы, на которые ссылаются конфиги.

Если конфигурация содержит абсолютный путь к файлу вне repository,
например путь внутри:

```
~/Pictures/
~/Изображения/
~/Downloads/
~/.local/share/
~/.config/
```

проверь, существует ли сам ресурс и находится ли он в repository.

Не копируй автоматически большие или сомнительно лицензированные
файлы только потому, что они используются системой.

Не добавляй новые assets в repository самостоятельно без запроса
пользователя.

============================================================
ПРОВЕРКА ПОСЛЕ УСТАНОВКИ
========================

После восстановления:

1. Проверить наличие managed директорий и файлов.

2. Проверить владельца файлов:
   они должны принадлежать текущему пользователю.

3. Проверить ключевые Hyprland-конфиги.

4. Проверить:

   * hyprland.lua;
   * monitors.lua;
   * workspaces.lua;
   * binds.lua;
   * inputs.lua;
   * decorations.lua;
   * colors.lua;
   * windowrules.lua.

5. Проверить наличие программ, вызываемых из конфигураций.

6. Проверить Noctalia.

7. Проверить Kitty.

8. Проверить Fish.

9. Проверить GTK/Qt/KDE/XSettingsd настройки.

10. Проверить внешние assets, особенно wallpaper.

11. Если возможно, выполнить безопасную проверку конфигурации
    Hyprland перед перезапуском текущей сессии.

12. Не перезапускай Hyprland автоматически.

Сначала сообщи пользователю результат проверки.

============================================================
ПОВЕДЕНИЕ ПРИ ОШИБКАХ
=====================

Если обнаружена проблема:

* не скрывай её;
* не продолжай разрушительные действия ради
  "автоматического завершения";
* сообщи, какой файл, программа или путь вызвал проблему;
* объясни причину;
* предложи минимальное исправление.

Не исправляй конфигурацию наугад.

Если проблема находится в install.sh:

* сначала опиши проблему;
* не меняй installer автоматически;
* предложи минимальный патч;
* после согласования пользователя можно вносить изменение.

Если восстановление прервалось после создания backup,
сообщи пользователю расположение backup.

Не удаляй backup автоматически.

============================================================
ВАЖНЫЙ ПРИНЦИП
==============

Repository является source of truth для managed пользовательских
конфигураций.

Но repository НЕ является полным образом всей операционной системы.

Не следует автоматически считать частью dotfiles:

* системные пакеты;
* /etc;
* драйверы;
* bootloader;
* kernel;
* hardware configuration;
* приватные данные;
* browser profiles;
* VPN profiles;
* SSH keys;
* secrets;
* runtime state.

Assets, находящиеся в repository, также не означают,
что они должны автоматически устанавливаться или применяться.

Цель восстановления:

```
максимально воспроизводимый пользовательский desktop
```

а не:

```
слепое клонирование всей системы.
```

============================================================
ПЕРЕД ЛЮБЫМ ВОССТАНОВЛЕНИЕМ
===========================

Сначала:

1. Изучи install.sh.
2. Изучи MAPPINGS.
3. Изучи структуру config/.
4. Определи зависимости конфигурации.
5. Проверь наличие необходимых программ.
6. Проверь внешние assets и wallpaper.
7. Определи, какие targets реально будут изменены.
8. Покажи пользователю план, если операция затрагивает существующие
   пользовательские файлы.
9. Только после подтверждения выполняй потенциально изменяющие систему
   действия.

При восстановлении используй install.sh как основной механизм,
если пользователь не попросил выполнить отдельные ручные действия.

Не выполняй опасные команды молча.

Не удаляй существующие пользовательские данные без backup.

Не изменяй конфигурацию, которая не относится к managed scope,
только ради достижения "похожего" результата.
